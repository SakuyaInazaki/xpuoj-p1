# 判题机实验方法学（09-04 圈86 固化）

三个脚本配套使用，解决「判题机噪声比效应大」这个核心困难。

## 1. `mnorm.py` —— 机器签名回归
两台判题机的差异**逐案不同**（不是均匀缩放）：compute-bound 的 c1/c2 被拖慢 2~2.9%，
memory-bound 的 c11/c12 几乎为 0。所以**「拿未触碰案取平均」会给出假阳性**——
本轮据此推翻过两个自己的结论（md GROUP_M 的「−2%」、量化目标的「−1.5%」）。

    signature()  用两次同码锚对(138154/138157, 138164/138166)拟合出逐案签名 s_i（均值归一）
    verdict(v, a, touched)  在未触碰案上最小二乘拟合机器项 m，残差 = d_i − m·s_i

全案触碰时用两参数 µs 尺度拟合：`Δtk_i(µs) = m·s_i·tk_i/100 + c`，c 就是效应。
单次 A/B 的检出下限约 **±1%**（逐案）或 **±10~20 µs**（全案常数项）。

## 2. `sqnr.py` —— 精度仪表
**Accepted 的提交也带逐 testcase 的 SQNR**，基线最差余量 +1.12 dB（阈值 22.0）。
可以直接当精度仪表用，不必等 WrongAnswer。
注意 `testcaseResult` 的迭代顺序在提交间不稳定 ⇒ **只能比集合，不能比序号**。

## 3. `run_batch.py` —— 提交+轮询+回归+SQNR 一条龙
    python3 scripts/run_batch.py "文件:标签:触碰案(逗号分隔)" ... --anchor p1/kernel.py
触碰案留空 = 全案触碰。raw 折算公式是 `-Σ(r_i/100 · tk_i · SENS_i)/12`，**别漏 tk 因子**。

## TLE 的两种形态（必须分清）
- **一行 SQNR 都不打印** = 编译期爆炸（ptxas/寄存器）。见 V631/V651/V655/V656a/V675a。
- **两组 SQNR 都打印并通过后才挂** = **误伤了样例槽**。判题机的 tc0 是一个
  **不在 `_KNOWN12` 里的形状**，任何作用于未知形状的前置链（量化器/排序/元数据）
  改动都会打挂它 ⇒ **这类改动必须 `_FL[0] == 1` 门控**。见 V672/V673 → V674 的三步隔离。

榜面 = display − 10，取历史最大值。tb 有单案 8 倍级异常（实录 SID138488 的 c4）。
