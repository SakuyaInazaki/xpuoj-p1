## Concrete inherited static-weight risks

- `_get_full_weights` final effective definition **4546–4571** keys only three expert weight shapes (**4547–4551**). A new same-shape weight object hits the prior all-gather/cat result at **4552–4554**. This applies to S1/S2 through `_run_replicated` **6359–6361**. It is an existing baseline stale-weight risk, not a new layout or hybrid bug.
- `_get_full_fp8_weights` **3769–3786** similarly keys only shapes, hits at **3775–3777**, and therefore may return stale quantized GU/Down before the upstream full-weight cache is queried. Fixing only `_get_full_weights` is insufficient.
- `_get_int_gu` **6313–6329** keys `(gu_q.shape, gran)` at **6314**; `_gu_bnorm` **6291–6307** keys `gu_q.shape` at **6293**. If their input quantized tensors are refreshed with equal shapes, both still return derived values from the previous tensors. S1 consumes these via new token/parameter producer **S1:6456–6458** and consumer **S1:6590–6595**; S2 MDg consumes them via **S2:6613–6616**. S2 pre_nf receives inherited `_dir_ah/_dir_wi/_dir_scl` freshly constructed each call but their bnorm can be stale.
- `_get_full_fp8_weights_lowmem_tiled` **3845–3853** has the same shape-only issue for c9/c10; outside S1/S2 target scope. `_get_static_fp8` **3968–3975** and `_get_static_int8_down` **3954–3958** similarly omit source object identity; these are other baseline paths, not new helper dependencies in the selected c4/c6 paths.
- `_get_down_static_scale` **7468–7473** is better: it includes `id(dn_q),id(dn_s)` and stores strong references to those tensors at **7490–7492**. New same-shape *derived* DN tensor objects invalidate this cache, but it cannot repair stale tensors returned upstream. Same-object in-place changes remain undetected.
- `_get_static_cache` **4375–4388** keys identities, shapes and topk but returns before examining contents. Different object identities invalidate; same-object in-place mutation does not. Its entry only retains derived `gate_up`, so identity reuse after source destruction is also a conditional concern. This generic path is bypassed by the selected c4/c6 replicated dispatch.

A→B→A distinction: same-shape A/B can hit stale A on B immediately in the above shape-only caches. Different shapes cause single-entry `_FULL_WEIGHT_CACHE`, `_FULL_FP8_CACHE`, `_INT_GU_CACHE` and `_BNORM_CACHE` to clear/rebuild on miss; returning to A generally rebuilds if B actually touched the cache. No need to add topk to a weight-only mathematical cache, but test-boundary handling must include all static sources and relevant scalar parameters where their derived value depends on them.

Minimal repair proposal for a separate correctness candidate: key the replicated source-weight caches by current source objects plus shape, and propagate input identity through `_get_full_fp8_weights`, `_get_int_gu`, `_gu_bnorm`; retain strong source references in cache entries and validate `is` on hit to avoid id reuse. Alternatively centralize one static-source generation token and clear all affected derived caches when the source tuple changes. Object identity cannot detect same-object in-place mutation: the problem statement permits static parameters to change on a new test point but does not guarantee new objects. Do not claim complete contract compliance from identity alone; robust mutation support requires an allowed boundary/version signal or content checking. `_version` is forbidden in the supplied discussion. Do not introduce a tensor content CPU synchronization into timed calls without separate evaluation.
