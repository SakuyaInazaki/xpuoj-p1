# 01 提交代码完整流程

## 0. 提交前检查

```bash
cd /home/sakimi26/xpuoj-p1

# Python 文件至少要通过语法编译
python -m py_compile p1/<candidate>.py

# 如果从当前 base 改出来，先 diff，确认只有目标改动
diff -u p1/kernel.py p1/<candidate>.py | head -200

# 确认当前 scoreboard / submissionCount（默认 contest 13 / problem 1）
python scripts/best_score.py
```

GPU kernel 类代码通常无法本地完整编译运行，`py_compile` 只查 Python 语法；
真正的编译/运行错误要等远程返回。

## 1. 提交命令（仓库自带脚本）

```bash
cd /home/sakimi26/xpuoj-p1

# 阻塞式提交并轮询
python scripts/submit.py p1/<candidate>.py --poll --interval 10 --timeout 1800 \
  2>&1 | tee logs/submit_<candidate>.log
```

参数：
- `file`：要提交的 Python 文件，必须是绝对或相对路径。
- `--poll`：提交后轮询到终态。
- `--interval`：轮询间隔秒。
- `--timeout`：轮询总超时秒。注意这只是**本地轮询超时**，不代表平台评测失败。
- `--compile-and-run-options`：JSON 对象，一般用默认 `{}`。

### 不阻塞提交（推荐在 Pending 偶发时使用）

```bash
cd /home/sakimi26/xpuoj-p1
python scripts/submit.py p1/<candidate>.py 2>&1 | tee logs/submit_<candidate>.log
# 输出: submitted submissionId=117xxx
```

随后用独立工具或 API 查：

```bash
python "桌面-XPUOJ提交与平台说明/tools/xpuoj_status.py" 117xxx --cases
```

### 换其他题目

仓库 `scripts/xpuoj_api.py` 顶部写死：

```python
CONTEST_ID = 13
PROBLEM_ORDER = 1
LANG = "<题目要求的 language>"
```

做其他题目前，先确认题目要求的 `language`，再改仓库脚本常量或使用独立工具传参：

```bash
python "桌面-XPUOJ提交与平台说明/tools/xpuoj_submit.py" FILE \
  --contest-id 13 --problem-order 2 --language <题目要求的language> \
  --poll --interval 10 --timeout 1800
```

## 2. 日志规范（强烈建议）

- 候选日志：`logs/submit_<候选名>.log`
- 同窗口对照日志：`logs/submit_<候选名>_control.log` 或 `submit_<候选名>_r2_control_first.log`
- 如果不用 `--poll`，日志只会有 `submitted submissionId=...`；最终状态需从 API 补记。

## 3. 提交后状态机

- `Pending`：排队/评测中。
- `Running`：少见，编译或评测中。
- `Accepted`：通过全部测试点（可能 displayScore 较低，但 status 是 Accepted）。
- `WrongAnswer`：有测试点失败。必须查 `userError`，可能是 SQNR、determinism、Python 异常、OOR 等。
- `TimeLimitExceeded`：总 500 秒问题时间限制或单 kernel 超时。
- 状态不一定立刻从 Pending 变化，见 `04-Pending与平台异常处理.md`。

## 4. 查询状态 / 结果

```bash
# 最近提交列表（只回最近约 10 条，不要指望翻历史）
python - <<'PY'
import sys
sys.path.insert(0,'scripts')
from xpuoj_api import Client
c=Client()
for s in c.list_submissions(10):
    print(s['id'], s['status'], s.get('displayScore'), s.get('timeUsed'))
PY

# 指定 submission 详情
python - <<'PY'
import sys, json
sys.path.insert(0,'scripts')
from xpuoj_api import Client
c=Client()
d=c.get_detail(117300).json()
print(json.dumps(d['meta'], ensure_ascii=False, indent=2))
print(json.dumps(d['progress'], ensure_ascii=False, indent=2)[:2000])
PY
```

## 5. 提交后建议动作

1. 先记下 submissionId。
2. 若 `--poll` 因工具层 300s 被杀，不要重新提交；先查详情。
3. 出结果后解析逐点 tk/tb，判断哪些 case 变快/变慢。
4. 如果是候选实验，紧接着投当前 base 做同窗口对照（见 `03-噪声与同窗口A-B测试.md`）。
5. 保存候选源码，必要时复制为 `p1/kernel_<submissionId>_backup.py`。

## 6. 最省事的实验流程（推荐）

```bash
cd /home/sakimi26/xpuoj-p1

# A）候选
python scripts/submit.py p1/kernel_v999_candidate.py --poll --interval 10 --timeout 1800 \
  2>&1 | tee logs/submit_v999_candidate.log

# B）同窗口当前 base 对照
python scripts/submit.py p1/kernel.py --poll --interval 10 --timeout 1800 \
  2>&1 | tee logs/submit_v999_control.log

# C）解析两边的逐点 tk/tb，比较 case 级差异
python "桌面-XPUOJ提交与平台说明/tools/xpuoj_status.py" <候选id> --cases
python "桌面-XPUOJ提交与平台说明/tools/xpuoj_status.py" <对照id> --cases
```

只有两对以上同窗口 A/B 方向一致才晋升。
