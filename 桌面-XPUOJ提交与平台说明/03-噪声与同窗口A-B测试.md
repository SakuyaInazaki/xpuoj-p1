# 03 评测噪声与同窗口 A/B 测试

## 噪声有多大（历史优化题实测）

- 同一份代码、不同时间提交，`timeUsed` 可差 **0.5-1.0ms 以上**。
- 某些大 case 的 tk 尤其飘；跨窗口比较会误判。
- raw / displayScore 还受 `tb_time_ms` 异常影响，更不能作为速度依据。

同一份代码的典型 timeUsed 波动：

```text
代码 A: 42839 / 42157
代码 B: 42779 / 42985
代码 C: 43266 / 43325
同一天不同窗口: 43100 ~ 43800 都可能出现
```

## 不能这样做

1. 拿候选今天的 timeUsed 和 base 昨天的 timeUsed 比。
2. 第一窗候选大赚就直接晋升。
3. 重复提交同一文件去碰 tb 异常或快窗。
4. 只看 raw/displayScore 判断速度。

## 正确做法：同窗口 A/B

每个候选至少安排 **两对**：

```text
第 1 对：候选 -> 当前 base（紧挨着提交）
第 2 对：当前 base -> 候选（顺序反过来，排除顺序/热窗口偏差）
```

命令：

```bash
cd /home/sakimi26/xpuoj-p1

# 第 1 对
python scripts/submit.py p1/kernel_v999.py --poll --interval 10 --timeout 1800 2>&1 | tee logs/submit_v999.log
python scripts/submit.py p1/kernel.py --poll --interval 10 --timeout 1800 2>&1 | tee logs/submit_v999_control.log

# 第 2 对（反向）
python scripts/submit.py p1/kernel.py --poll --interval 10 --timeout 1800 2>&1 | tee logs/submit_v999_r2_control_first.log
python scripts/submit.py p1/kernel_v999.py --poll --interval 10 --timeout 1800 2>&1 | tee logs/submit_v999_r2_candidate.log
```

然后逐 case 比较：

```bash
python "桌面-XPUOJ提交与平台说明/tools/xpuoj_status.py" <候选id> --cases
python "桌面-XPUOJ提交与平台说明/tools/xpuoj_status.py" <对照id> --cases
```

## 晋升判据（经验）

- **两对同窗口 A/B 的 tk 方向一致才晋升。**
- 只改某个 case 的候选，重点看该 case 差值；其他 case 的波动是噪声。
- 如果两对方向相反：
  - 对重要候选做第 3、第 4 窗 tie-break；
  - 多数窗仍不一致就关闭，不要反复试。
- raw 高但 timeUsed 不行的，一律不晋升。
- 平台保留历史最佳，错误实验不会扣 best，但会占用 submissionCount（扣罚已到上限 10，可忽略）。

## 本会话真实例子（教训）

| 候选 | 第一窗 | 反向窗 | 结论 |
|---|---|---|---|
| 量化 tile 调整 | 目标 case -0.257ms | 目标 case +0.200ms | 继续 3/4 窗，3/4 更快，晋升 |
| gather tile 调整 | 总 -0.423ms | 总 +0.212ms，第三窗 +0.579ms | 关闭 |
| 某 case 专属 tile | 目标 case 大赚 | 目标 case 小亏 | 关闭 |
| 结构改动 | 目标 case 13.286ms | — | 明显慢，直接关闭 |

## 注意 tb 异常

以下 raw 高分都不代表真实性能：

```text
某提交 case5 tb=264.994 -> raw 76.67，成为 scoreboard best
另一提交 case9 tb=41.192 -> raw 75.75
类似 tb 异常多次出现
```

判断速度只认 `tk_time_ms` 和 `timeUsed`。

## 提交纪律总结

1. 候选和 base 必须同窗口紧挨提交。
2. 至少两对，必要时 3-4 窗。
3. 只看 tk/timeUsed，不看 raw/tb。
4. 保存每窗 submissionId 和日志。
5. 候选从当前 `p1/kernel.py` 复制，不要从旧备份改。
