追加结论：
- `num_ctas=2` 在 fused kernel 上直接 PassManager 失败，仅用于 down TMA 也明显变慢；不要继续。
- routing TMA 未超过当前路径。
- case2 gateup s4 变慢。
- fused gateup 的 persistent/M-only 重排虽然理论可减少 per-row amax atomic 次数，
  但均出现 SQNR 严重错误（仅 case2 普通路径通过），已放弃该线。
- **116310 / `kernel_v98_token_row.py` 仍是当前实际性能 base，`p1/kernel.py` 保持不动。**

## 关键经验（新增）

1. **host-side `TensorDescriptor` 可用且有效**：
   - `from triton.tools.tensor_descriptor import TensorDescriptor` 通过校验；
   - B flatten 成 [E*N,K] 后 block [256,128]，kernel 用 `B_DESC.load([expert*N+pid_n*BN, k*BK])`
     再 `tl.dot(a, b.T, acc)`。
   - device-side `tl.make_tensor_descriptor` 在当前远程 Triton-dist 版本会报
     `_semantic` 错误，不要再用。
2. **有效组合**：TMA down B + down 激活 per-row scale + token gather per-row amax/scale
   + fused gateup row-A scale（116310）。这些改动避免单一 global amax 的 atomic 争用。
3. **TMA 不适用于**：
   - case2 plain gateup（116244 变慢）；
   - fused gateup（116249 变慢）；
   - C TMA store、A+B 双 TMA、contiguous-M 调度、BN128、BK256/s2、num_stages=4；
   - case2 token per-row（116315 变慢）、SwiGLU act 缓存（116260 变慢）。
4. 噪声仍大：同一 v98 两次 timeUsed 差约 0.64ms，判断需看同窗口对照，不要只看一次 raw。
